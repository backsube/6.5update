# NOUMENON 게임 개발 PRD

문서 버전: 0.6.5  
제품 단계: 플레이 가능한 프로토타입  
이 문서는 현재 코드와 씬에서 확인되는 구현을 기준으로 작성했으며, 미확정 기획은 별도로 표시한다.

## 1. 제품 개요

NOUMENON은 위험 지역을 탐색하고 적과 교전하며 가치 있는 자원을 확보한 뒤 생환하는 **탑다운/쿼터뷰 세션형 액션 루팅 게임**을 지향한다. 플레이어는 제한된 인벤토리 공간과 전투 자원을 관리하면서 위험과 보상의 균형을 선택한다.

### 핵심 판타지

“적대적이고 불확실한 공간에 진입해 살아남고, 무엇을 가져갈지 판단한 뒤 더 강해져 돌아온다.”

### 목표 플랫폼

- 우선 목표: Windows PC
- 입력: 키보드 + 마우스
- 엔진: Unity 6 / URP

## 2. 타깃 사용자

- 전투와 탐색이 결합된 세션형 게임을 선호하는 플레이어
- 공간 제한형 인벤토리와 아이템 선택의 긴장감을 즐기는 플레이어
- 짧은 플레이 세션에서도 명확한 획득과 손실을 원하는 플레이어

## 3. 핵심 게임 루프

1. 장비와 목표를 준비한다. *(로비/준비 단계는 미구현)*
2. 위험 지역에 진입한다.
3. 맵을 탐색하며 아이템, 상자, 적을 발견한다.
4. 교전하거나 회피하고 자원을 획득한다.
5. 제한된 인벤토리에 어떤 아이템을 담을지 결정한다.
6. 탈출 지점에 도달하거나 사망한다. *(실제 탈출 지점은 미완성)*
7. 처치, 아이템 가치, 시간, 성공 여부를 정산한다.
8. 획득 자원으로 다음 세션을 준비한다. *(메타 진행은 미구현)*

## 4. 핵심 시스템 요구사항

### 4.1 이동과 카메라

- 플레이어는 `WASD`로 지형 위를 이동한다.
- 캐릭터와 조준 방향은 마우스 월드 좌표를 따른다.
- 카메라는 플레이어를 추적하고 플레이 공간을 명확히 보여야 한다.
- 인벤토리가 열린 동안 이동/전투 입력 충돌을 최소화한다.

### 4.2 전투

- 우클릭으로 조준하고 좌클릭으로 사격한다.
- 무기에는 탄창, 예비 탄약, 발사 간격, 재장전 시간이 존재한다.
- 적중 판정은 월드 콜라이더 및 적 체력 시스템과 연결된다.
- 적 사격도 플레이어 체력에 피해를 준다.
- 피격 피드백, 사운드, VFX와 무기 다양화는 후속 콘텐츠 범위다.

### 4.3 적과 팩션

- 적은 시야 거리/각도와 청각을 통해 플레이어를 감지한다.
- Reaver는 적대 세력으로, Maintainer는 경고 후 조건부 적대로 동작할 수 있다.
- 적은 Idle → Alert → Aggro/Retreat → Dead 상태 흐름을 가진다.
- 동료 경계 전파와 소리 반응을 통해 전투가 공간적으로 확산된다.
- 사망한 적은 루팅 가능한 대상으로 전환된다.

### 4.4 상호작용

- 플레이어 반경 내 가장 가까운 대상 하나를 선택한다.
- `F`를 일정 시간 누르면 아이템 획득 또는 상자 열기가 실행된다.
- 진행 상태와 대상 강조가 시각적으로 명확해야 한다.
- 오브젝트가 겹쳐도 이미 열린 상자 때문에 다른 아이템 상호작용이 막히지 않아야 한다.

### 4.5 인벤토리와 루팅

- 플레이어 인벤토리는 8×6 칸의 공간 제한형 그리드다.
- 아이템은 폭·높이 크기를 가지며 여러 칸을 점유할 수 있다.
- 주변 아이템, 상자, 플레이어 가방 사이에서 드래그 앤 드롭한다.
- 드래그 시작 위치를 유지해 다칸 아이템을 직관적으로 배치한다.
- 충돌하거나 범위를 벗어난 배치는 취소되고 원래 위치가 복구되어야 한다.
- 아이콘, 툴팁, 수량, 선택/호버 상태를 제공한다.
- UI 장식 요소는 슬롯의 포인터 이벤트를 가로채면 안 된다.

### 4.6 아이템과 경제

- 아이템 데이터는 이름, 아이콘, 크기, 무게, 솔라늄 기준 가격을 가진다.
- 세션 중 획득한 아이템과 가치는 결과에 누적된다.
- 무게 페널티, 상점, 제작, 장착 능력치와 영구 보관함은 후속 개발 범위다.

### 4.7 세션과 정산

- 세션은 시작 시간부터 플레이 시간, 처치 수, 획득 목록, 솔라늄을 기록한다.
- 탈출 성공 또는 사망으로 세션이 종료된다.
- 결과 UI는 성공 여부와 주요 성과를 표시한다.
- 현재 복귀 동작은 주 씬 재시작이며, 추후 로비 씬으로 교체한다.

## 5. 레벨 디자인 요구사항

### 공간 구조

- 안전한 진입부, 탐색 구역, 교전 구역, 고가치 루팅 구역, 탈출 구역을 구분한다.
- 각 구역에는 플레이어가 위치를 기억할 수 있는 랜드마크가 필요하다.
- 주 동선 외에 위험하지만 보상이 큰 우회 경로를 제공한다.
- 전투 공간은 이동, 사선, 엄폐, 후퇴 경로가 모두 존재해야 한다.

### 배치 원칙

- 적과 루팅 보상은 위험도에 비례한다.
- 상호작용 오브젝트는 식별 가능한 실루엣과 조명을 가진다.
- 적 스폰은 플레이어의 즉시 시야 안에서 부자연스럽게 발생하지 않는다.
- NavMesh 단절, 끼임, 도달 불가능한 루팅 오브젝트를 허용하지 않는다.
- 플레이 영역 경계는 보이지 않는 벽에만 의존하지 말고 환경 언어로 설명한다.

### 성능 목표(초기 가이드)

- 목표: Windows 기준 1080p 60 FPS
- 반복 환경물은 프리팹/인스턴싱을 사용한다.
- 고폴리 모델은 LOD를 구성하고 불필요한 Read/Write를 끈다.
- 텍스처는 용도에 맞는 해상도와 압축을 사용한다.
- 실시간 조명, 그림자, 투명 오브젝트와 파티클 오버드로우를 제한한다.

## 6. 아트 디렉션 요구사항

구체적인 색채/시대/세계관 스타일 가이드는 아직 확정 문서가 없으므로 기존 `parkseongbin` 씬의 분위기를 기준점으로 삼는다. 대규모 스타일 변경 전에는 무드보드와 대표 구역 한 곳의 아트 패스를 먼저 승인받는다.

- 모든 신규 머티리얼은 URP 호환이어야 한다.
- 환경, 캐릭터, 프롭, VFX를 분리해 관리한다.
- 실제 플레이 카메라 거리에서 읽히는 실루엣과 색 대비를 우선한다.
- 루팅 가능 오브젝트와 위험 요소는 환경 속에서도 명확히 구분되어야 한다.

## 7. UX 요구사항

- 입력 결과는 즉시 시각/청각 피드백을 제공한다.
- 인벤토리 슬롯의 어느 지점을 잡아도 동일하게 드래그가 시작되어야 한다.
- 상호작용 키와 진행 상태를 화면에서 이해할 수 있어야 한다.
- 전투 중 체력, 탄약, 조준 상태를 쉽게 읽을 수 있어야 한다.
- 16:9 1080p를 기준으로 시작하되 다른 해상도에서 UI 겹침을 검증한다.

## 8. 마일스톤 제안

### M1 — 플레이 루프 완성

- 탈출 지점 구현
- 세션 성공/실패와 결과 UI 연결
- 로비 또는 준비 씬 연결
- 전체 루프 1회 플레이 가능

### M2 — 레벨 Vertical Slice

- 대표 구역 블록아웃 및 아트 패스
- 적/루팅/엄폐/조명 배치
- NavMesh와 성능 1차 검증

### M3 — 콘텐츠와 메타

- 아이템/무기/적 변형 확장
- 장착, 보관함, 상점 또는 제작
- 세이브 데이터와 진행 구조

### M4 — Alpha 안정화

- 밸런스와 UX 개선
- 옵션/키 설정/해상도 대응
- 빌드 자동화, 회귀 테스트, 성능 최적화

## 9. Version 6.5 인수 조건

- Unity 6에서 프로젝트가 열리고 컴파일 오류가 없다.
- `parkseongbin` 씬이 원본 오브젝트 및 게임플레이 참조와 함께 로드된다.
- 이동, 조준, 사격, 적 AI, 상호작용, 루팅, 인벤토리 흐름이 유지된다.
- 첫 번째 인벤토리 슬롯을 포함한 전체 슬롯 영역에서 드래그가 시작된다.
- 디자이너가 신규 3D 에셋과 맵 변경을 독립 브랜치에서 수행할 수 있다.
- 변경 사항과 `.meta` 파일이 Git에서 추적되고 Unity 생성 캐시는 제외된다.
